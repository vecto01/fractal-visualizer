# План проекта: Интерактивная визуализация фракталов

## Описание
Проект представляет собой интерактивную визуализацию фракталов (например, множество Мандельброта) с возможностью изменения параметров в реальном времени. Пользователь сможет:
- Масштабировать и перемещать область просмотра.
- Изменять цветовые схемы.
- Переключаться между светлой и тёмной темой.
- Экспортировать изображение.

## Технологии
- **Рендеринг**: HTML5 Canvas или WebGL (для производительности).
- **UI**: Чистый CSS/JS, адаптивный дизайн.
- **Анимации**: Плавные переходы при изменении параметров.
- **Темы**: Переключение между светлой и тёмной темой (localStorage).

---

## Задачи

### Фаза 1: Базовая визуализация
1. **Создать структуру проекта** (`index.html`, `style.css`, `script.js`).
2. **Реализовать рендеринг фрактала** (множество Мандельброта) на Canvas.
   - Алгоритм: итеративный расчёт для каждого пикселя.
   - Оптимизация: веб-воркер для ускорения расчётов (опционально).
3. **Добавить базовый UI**:
   - Кнопки для увеличения/уменьшения масштаба.
   - Ползунок для изменения максимального количества итераций.
4. **Сохранить состояние** в localStorage (масштаб, позиция, параметры).

### Фаза 2: Интерактивность и анимации
1. **Добавить плавное перемещение** по фракталу (drag-and-zoom).
2. **Реализовать анимацию** при изменении параметров (например, плавный переход при изменении цветовой схемы).
3. **Добавить цветовые схемы** (например, радужная, чёрно-белая, пользовательская).

### Фаза 3: Темы и финишная полировка
1. **Реализовать переключение тем** (светлая/тёмная) с сохранением в localStorage.
2. **Добавить кнопку экспорта** изображения (PNG).
3. **UI-аудит** с помощью `ui_audit`:
   - Проверить все состояния (пустой экран, загрузка, hover, мобильная версия).
   - Убедиться в отсутствии jank в анимациях.
4. **Оптимизации**:
   - Ленивая загрузка ассетов.
   - Кеширование расчётов фракталов.

### Фаза 4: Тестирование и публикация
1. **Написать автоматические тесты** (например, для проверки корректности рендеринга при разных параметрах).
2. **Провести ручное тестирование** на разных устройствах.
3. **Опубликовать проект** на GitHub (`github_publish_project`).

## Критерий готовности фазы
- Фаза считается завершённой, если все задачи выполнены и проект работает стабильно на всех целевых устройствах.
- Перед переходом к следующей фазе требуется подтверждение владельца.
